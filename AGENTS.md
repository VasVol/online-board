# Поле / online-board

Личная онлайн-доска Василия для занятий математикой. Сначала Debian 13 / GNOME Flashback / X11 на ноутбуке, затем свой сервер. Не разворачивать на стороннем хостинге без запроса.

## Прочитайте перед изменениями

- `README.md`: запуск, пользовательские функции, проверенные ограничения.
- `docs/RESEARCH.md`: почему Excalidraw + Yjs; не заменять SDK на текущий tldraw без анализа лицензии.
- `docs/ARCHITECTURE.md`: протокол, сохранение, права доступа.
- `docs/PLAN.md`: последовательность развития.
- `docs/DEPLOYMENT.md`: действующее размещение, DNS и инструкции автоматического обновления. Пользователь разрешил публикацию кода в существующий `VasVol/online-board` и размещение на своём сервере; это не разрешение на покупку другого тарифа или перенос NS основного домена.
- В Cloudflare менять только настройки, относящиеся к `vasilyvolovich.com` и размещению доски на `board.vasilyvolovich.com`. Доска перенесена на `ssh ovh-vps`; поддомен направлен A-записью прямо на VPS, HTTPS обслуживает Caddy. Старые Cloudflare connector на ноутбуке и VPS выключены; запускать их нельзя. Пути данных, службы, backup и проверки описаны в `docs/DEPLOYMENT.md`. Другие домены, сервисы и общие настройки аккаунта не изменять.
- `docs/LAPTOP_HOSTING.md`: проверенный временный HTTPS-доступ с ноутбука через Pinggy, команды `online-board-public`, лимит 60 минут, зависимость браузера от текущих настроек сети. Не выдавать временный туннель за постоянный адрес; не менять системный прокси и питание без необходимости. Не публиковать файл owner-key, state-файл адреса и логи с ключами.
- `docs/UNIFORM_PEN.md`: постоянная толщина, воспроизводимая адаптация рендерера и её тесты.
- `docs/VERIFICATION.md`: проведённые проверки и первоначальный рабочий запуск. Перед запуском dev проверьте, не занят ли порт 3001 пользовательским сервисом `online-board`/`pole`; не запускайте второй процесс поверх него.

## Работа с проектом

- Node >=20.19, npm, TypeScript, React 18, Excalidraw 0.18.1. Версии фиксируются `package-lock.json`; устанавливать через `npm ci`.
- `npm run dev`: Vite 5173 + API 3001. `npm run build && npm start`: production, один порт 3001.
- `npm run check`: typecheck, unit/integration, браузерные E2E, production build. Запускать перед коммитом. Hook `.githooks/pre-commit` устанавливается `npm install`/`npm ci`; существующий чужой hooksPath не перезаписываем.
- Для E2E: `npx playwright install chromium --only-shell`. Тесты работают в отдельном временном каталоге данных на 4310/4311. Не использовать пользовательский `data/` в тестах.
- Новый баг синхронизации воспроизводить двумя независимыми клиентами, а не одной вкладкой. Проверять offline/reconnect и reload. Не подменять реальную синхронизацию BroadcastChannel.
- Не коммитить `data/`, backup, owner-key, ссылки с секретами, `.env`, изображения учеников или trace с реальными данными.
- Не стирать/пересоздавать БД пользователя ради проверки. Миграции версионировать; перед миграциями нужна резервная копия.
- Пользователь разрешил постоянный рабочий порядок: **после завершённой задачи проверить, закоммитить, отправить в `VasVol/online-board` и дождаться проверенного обновления VPS**. Не спрашивать это разрешение заново. Явное указание «только файлы», «без коммита/push/deploy» или «пока не публиковать» отменяет этот порядок для соответствующей задачи. Не создавать коммиты при каждом сохранении файла.

## Обязательный порядок завершения задачи для LLM

1. Перед изменениями прочитать `git status`, текущую ветку и `docs/DEPLOYMENT.md`. Сохранить незавершённые изменения пользователя; не делать reset/clean, force push или общий `git add .` без просмотра состава изменений. Обычные готовые изменения публикуются в `main`; работа в `codex/...` попадёт на VPS только после включения в `main`.
2. Реализовать законченное изменение и подходящие проверки, обновить документацию. Для изменений схемы/формата хранения сначала приостановить автодеплой и подготовить отдельный план миграции/backup/совместимости. Не понижать требования CI ради зелёной проверки.
3. Просмотреть diff и список новых файлов; исключить секреты и реальные данные. Подготовить **ровно то дерево, которое тестируется**. Pre-commit откажет при unstaged/untracked файлах: несвязанные незавершённые изменения требуют отдельного worktree, а не их случайного включения в коммит.
4. `git add <просмотренные файлы>`, затем `git commit -m "..."`. Hook сам выполняет полный `npm run check`: TypeScript, unit/integration, тесты деплоя Python (stdlib), dev и production Playwright, production build. Не применять `--no-verify`, не отключать hooks/тесты. При ошибке исправить причину и повторить. Повторный отдельный `npm run check` после успешного hook без новых изменений не нужен.
5. `git push origin main` (для другой ветки — отправить её и включить в `main` обычным проверяемым порядком). При расхождении с remote сначала изучить и согласовать изменения, не перезаписывать историю.
6. Дождаться успешного workflow **Checks**, job **test**, step **Run full check** именно для отправленного SHA. VPS сам проверяет GitHub раз в 5–5,5 минут и устанавливает только успешно проверенный `push` в `main`; PR/другие ветки и failed/skipped/cancelled проверки не разрешают деплой.
7. Проверить `https://board.vasilyvolovich.com/api/health`: `ok=true`, `revision` равен `git rev-parse HEAD`. Посмотреть статус `ssh ovh-vps 'sudo python3 /usr/local/lib/pole-deploy/pole_deploy.py status'`. Фаза `deployed` или `up_to_date` с нужным SHA подтверждает итог. `waiting_for_ci`/`waiting_for_idle` — ещё не опубликовано; не выдавать push за завершённый deploy.
8. В отчёте дать коммит, результат проверок и факт обновления сайта либо конкретную причину ожидания. Сейчас пользователь явно разрешил обновления при открытых тестовых вкладках: на VPS `require_idle=false`, занятий пока нет. **Перед переходом к реальным занятиям** установить `require_idle=true` в `/etc/pole/deploy.json`: updater будет ждать минимум 60 секунд без участников. Во время занятий этот барьер не обходить без явного разрешения пользователя.

Автодеплой создаёт согласованный backup, проверяет отдельную тестовую БД и HTTPS/WebSocket, переключает `/opt/pole/current`. При неудаче возвращает прежний **код**, не старую БД; неудачный SHA блокируется до исправления или осознанного `retry`. Скрипт обновления и systemd units под root **не обновляются автоматически из репозитория**: изменения `deploy/automation/` и `deploy/server/` отдельно проверить и установить по `docs/DEPLOYMENT.md`. Не добавлять личный SSH-ключ или root-токен в GitHub.

## Инварианты

1. Одна страница = один Y.Doc. Каталог не загружает сцены. Комнаты освобождаются после последнего клиента. Списки досок и страниц всегда ограничены и имеют пагинацию.
2. Сначала синхронная запись обновления в SQLite, затем broadcast/ack. Никогда не показывать «Сохранено» лишь по наличию WebSocket.
3. Не заменять все объекты сценой одного клиента. Удаления — tombstones `isDeleted`, а не удаление Y.Map-ключа.
4. Ключ из `#key=` даёт права только на свою доску; owner-cookie даёт каталог и административные операции. WebSocket проверяет права и принадлежность страницы. Не логировать ключи/query/header/cookie.
5. Рисунки и изображения сохраняются на сервере; браузерный IndexedDB — дополнительная копия. Awareness эфемерен.
6. Взаимодействие с Excalidraw — через публичные API; единственное исключение — зафиксированная в `scripts/patch-excalidraw.mjs` адаптация толщины пера (публичного параметра в 0.18.1 нет); зависимость/адаптер при обновлении проверять браузерными тестами. У свободного пера нет встроенного dashed: наша конверсия после жеста обязательна. Использовать непрерывную кривую: ломаная с частыми точками начинает dash заново на каждом сегменте и выглядит сплошной. Проверять видимые промежутки на Canvas, не только поле strokeStyle.
7. L/C работают **при удержании**, игнорируют текстовые поля/редактирование текста, возвращают прежний инструмент. C создаёт окружность во всех направлениях перетаскивания.
8. Сохранять постоянную толщину свободного пера, включая живой штрих, PNG/SVG и production. Не заменять это конверсией только после pointerup и не переписывать пользовательские сцены. После обновления SDK проверить оба рендерера, мышь и нажим стилуса.
9. Не обещать отсутствие зависаний при произвольном числе объектов. Фиксировать конкретные замеры, среду и ограничения.

Новые функции оформлять отдельным слоем/модулем, а не наращивать универсальный компонент. Следующие крупные изменения: JSON-import, математические инструменты, аккаунты/роли, история/восстановление, квоты/метрики, распределённые комнаты.
