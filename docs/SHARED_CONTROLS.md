# Общая сетка и разовый сбор участников

27 октября 2026 изменения сначала проверены локально без публикации. Затем пользователь явно разрешил общий релиз. Публикация выполняется после полного локального и GitHub CI с отдельной миграцией схемы 1 → 2 по плану ниже.

## План миграции и совместимость

Перед будущей публикацией схемы 2: приостановить updater (`pole_deploy.py pause`), проверить отсутствие занятия и подготовить согласованный SQLite backup по DEPLOYMENT.md. Автоматизация текущей версии откажется устанавливать кандидат с отличающейся схемой; этот барьер не ослаблять.

Схема 1 → 2 добавляет в `boards` два поля: `gridEnabled` (0 по умолчанию) и `gridRevision` (0). Версионированная транзакционная миграция не меняет страницы, сцены, изображения, владельцев и ключи. Обычный запуск приложения отказывается автоматически мигрировать существующую схему 1. Проверить `npm run migrate -- /path/to/copied.sqlite` на копии: скрипт создаёт дополнительный согласованный backup с правами 0600, проверяет его и выполняет миграцию. Проверить сохранность данных, затем при остановленном приложении отдельно выполнить ту же согласованную операцию над рабочей базой и переключить код. До возобновления обновлений установить проверенную новую версию `deploy/automation/` по DEPLOYMENT.md: health поддерживает схемы 1 и 2, но сравнение структуры рабочей и кандидатной БД остаётся строгим. Установленные на ноутбуке launch-скрипты также требуют обновления через штатный установщик. После проверки HTTPS/WSS, прав доступа, сетки, сбора участников и нужного SHA возобновить updater. Старый код версии 1 отказывается открывать схему 2; откат требует совместимого кода, а не восстановления старой БД поверх новых рисунков. При ошибке миграции транзакция сохраняет схему 1.

## Протокол

Общая сетка — настройка доски, а не страницы. Изменение через авторизованный HTTP PATCH сначала записывается в SQLite, затем рассылается во все открытые комнаты доски. Начальный снимок приходит каждому новому WebSocket-клиенту. Монотонная ревизия не даёт запоздалому HTTP-ответу перезаписать более новое событие.

Разовый сбор — owner-only HTTP POST с целевой страницей и центром/масштабом камеры. Сервер проверяет владельца и принадлежность страницы, затем рассылает эфемерное сообщение всем текущим WebSocket-клиентам доски независимо от открытой страницы. Автор команды исключает себя по идентификатору своего окна. Команда не сохраняется и не повторяется после reload/reconnect: участники, отсутствовавшие в момент отправки, не перетягиваются задним числом. Смена страницы проходит обычную загрузку одного Y.Doc и flush текущих правок; каталог не загружает сцены других страниц. Следование (`userToFollow`) сбрасывается, повторные события одной команды игнорируются.

Новое серверное сообщение y-websocket типа 5 содержит JSON события `grid` или `gather`. Клиент не может отправлять команды этим каналом: входящий тип 5 сервер отвергает. Права владельца не берутся из awareness.
