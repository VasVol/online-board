# Поле — своя доска для занятий математикой

Самостоятельно размещаемая онлайн-доска на **Excalidraw + Yjs + SQLite**. Интерфейс на русском; ученики входят по ссылке без регистрации. Данные хранятся на вашем сервере, а не на excalidraw.com. Проект предназначен сначала для ноутбука, затем для обычного Linux-сервера.

## Возможности первой версии

- Одновременное рисование несколькими участниками, имена и курсоры, восстановление соединения.
- Draw, Eraser, Select, Hand; цвет и толщина пера, маркер, пунктир и точки. Перо пишет с постоянной толщиной без зависимости от скорости мыши и нажима стилуса.
- **Удерживайте L** и тяните мышь для прямой; **удерживайте C** для окружности. После отпускания возвращается прежний инструмент. Работает по физическим клавишам и при русской раскладке. Обычный инструмент эллипса остаётся доступен отдельно.
- Перемещение по бесконечной плоскости, масштаб, сетка, «Показать всё».
- Выделение, перемещение, копирование, дублирование, поворот, изменение размера, группы и слои — инструменты Excalidraw.
- Несколько именованных досок, несколько именованных страниц в каждой, поиск и пагинация. Рисунки закрытых страниц не держатся в редакторе.
- Undo/redo собственных правок, текст, фигуры, стрелки, изображения PNG/JPEG/WebP/GIF до 2 МБ.
- Ссылка с правом редактирования одной доски; её можно отозвать. Гость не видит каталог владельца.
- Экспорт страницы в `.excalidraw`, PNG и SVG через меню редактора. JSON-импорт в оболочку пока не реализован; `.excalidraw` открывается совместимым редактором.
- Серверное автосохранение, дополнительная копия страницы в IndexedDB, экспорт/восстановление ключа владельца, скрипт согласованного backup SQLite.

**Честные ограничения:** ластик удаляет целый штрих/объект; пиксельного ластика пока нет. Пунктир свободного пера после окончания жеста превращается в гладкую линию и не сохраняет давление стилуса. Временные L/C видны другим участникам после окончания жеста. Сетка/камера и настройки пера пока локальны для текущего редактора. История undo не сохраняется после перезагрузки или смены страницы. Одновременное изменение одного объекта имеет одного детерминированного победителя; это не посимвольная совместная работа внутри текста.

## Быстрый запуск на ноутбуке

На ноутбуке Василия установлен ярлык **«Поле — доска для математики»** на верхней панели GNOME Flashback. Он запускает пользовательский `pole.service`, ждёт готовности сервера и открывает `http://127.0.0.1:3001/` в обычном браузере. Повторное нажатие не запускает второй сервер. После перезагрузки можно снова нажать ярлык; автоматический старт при входе не включён.

Установка ярлыка в такой же среде после сборки: `npm run install:desktop`. Скрипт сохраняет копию настроек панели в `~/.local/state/online-board/`, добавляет только свой launcher и не переставляет другие значки. Управление: `systemctl --user stop pole`, `systemctl --user restart pole`, `journalctl --user -u pole`. Перед `npm run dev` остановите `pole`.

Нужен Node.js **20.19+** (на сервере/CI используется 22 LTS) и npm.

```bash
cd /home/vasily/Courses/online-board
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. Vite обслуживает интерфейс на 5173, API/WebSocket — на 3001. Сервер слушает сетевые интерфейсы: в той же Wi-Fi-сети можно открыть `http://IP_НОУТБУКА:5173` (если разрешает firewall). Адрес ноутбука можно посмотреть `hostname -I`. Откройте доску через этот адрес перед копированием гостевой ссылки. Ссылка с `localhost` не работает на другом компьютере.

Для рабочего запуска без Vite:

```bash
npm run build
npm start
```

Откройте **http://127.0.0.1:3001**. Выберите один адрес для регулярного использования: у `localhost`, `127.0.0.1` и сетевого IP разные cookie владельца. Для переноса каталога между адресами используйте ключ владельца. `npm run dev` и `npm start` одновременно используют один API-порт — перед переключением остановите dev через Ctrl+C. Шрифты редактора копируются из установленного пакета автоматически, внешняя CDN для них не нужна.

**В интернете:** нужен доступный извне адрес и HTTPS: домен + Caddy на сервере, либо туннель с поддержкой WebSocket к локальному порту 3001. Ноутбук должен оставаться включённым и не засыпать. Публичный адрес/туннель автоматически не создаётся. Пример Caddy — `deploy/Caddyfile.example`; домашний роутер/CGNAT могут не позволить обычный проброс порта. Не открывайте dev-сервер Vite в публичный интернет; публикуйте production.

На ноутбуке Василия теперь установлен пробный внешний доступ: **`online-board-public open`** запускает HTTPS-туннель Pinggy и открывает текущую ссылку; `online-board-public stop` выключает только туннель. Бесплатное подключение действует 60 минут, новый запуск получает другой адрес. Проверены два браузера, WSS и сохранение после перезапуска. Инструкция, особенности текущей сети и перенос доступа к старым доскам: [LAPTOP_HOSTING.md](docs/LAPTOP_HOSTING.md).

## Владение и доступ

При первом открытии браузер получает секретный HttpOnly cookie владельца. Регистрация не нужна. В каталоге отображаются доски именно этого владельца; у других браузеров другой каталог.

На главной нажмите **«Сохранить ключ владельца»** и храните `pole-owner-key.json` в надёжном месте. **«Восстановить доступ»** восстановит каталог в другом браузере. Этот файл даёт полный доступ ко всем вашим доскам — ученику передавайте только ссылку отдельной доски. Очистка cookie без сохранённого ключа лишит вас каталога (рисунки на сервере останутся).

Гость может редактировать рисунки, менять названия и создавать страницы. Удаление досок/страниц, получение и смена ключа доски доступны владельцу. Нельзя удалить последнюю страницу. Удаление скрывает данные; отдельной корзины/кнопки восстановления пока нет. Отозванная ссылка не удаляет уже полученные копии с чужих устройств.

## Настройки сервера

Для `npm start` переменные задаются окружением; `.env` автоматически **не читается**.

| Переменная      | По умолчанию | Назначение                                                                     |
| --------------- | ------------ | ------------------------------------------------------------------------------ |
| `PORT`          | `3001`       | HTTP и WebSocket                                                               |
| `HOST`          | `0.0.0.0`    | Интерфейс прослушивания; `127.0.0.1` для локального reverse proxy              |
| `DATA_DIR`      | `./data`     | Каталог SQLite, относительно рабочей директории                                |
| `PUBLIC_ORIGIN` | не задан     | Например `https://board.example.org`; задаёт Secure cookie и допустимый origin |
| `TRUST_LOCAL_PROXY` | `0` | `1` — доверять HTTPS-заголовку только от loopback-прокси; для локального туннеля |

Пример:

```bash
HOST=127.0.0.1 PUBLIC_ORIGIN=https://board.example.org npm start
```

`deploy/pole.service` — пример пользовательского systemd-сервиса для Debian. После сборки при желании установите:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/pole.service ~/.config/systemd/user/pole.service
systemctl --user daemon-reload
systemctl --user enable --now pole
journalctl --user -u pole -f
```

Он стартует при входе пользователя. Для работы после выхода нужен systemd linger либо системный unit — это отдельная настройка хостинга. Автозапуск код проекта сам не включает.

## Docker и перенос на сервер

Текущее состояние внешнего размещения, требования к серверу и схема автодеплоя: [DEPLOYMENT.md](docs/DEPLOYMENT.md).

```bash
cp .env.example .env
# Настройте PUBLIC_ORIGIN и BIND_ADDRESS.
docker compose up -d --build
```

По умолчанию наружу привязан только `127.0.0.1:3001`; TLS завершает Caddy. Для локальной сети можно задать `BIND_ADDRESS=0.0.0.0`. Рисунки, изображения, владельцы и ключи лежат в именованном volume `board-data`. **Не выполняйте `docker compose down -v`, если хотите сохранить их.** Docker-конфигурация предоставлена для переноса; основная проверка этой версии выполняется напрямую Node.js/Chromium.

Используйте **один процесс/одну реплику** приложения. Несколько процессов без общего транспорта обновлений не обеспечат правильную синхронизацию комнат. Наличие SQLite не делает rooms автоматически распределёнными.

## Сохранение и резервные копии

Основное хранилище: `data/board.sqlite` вместе с рабочими WAL-файлами. Обновление сначала пишется на диск, затем отправляется другим клиентам. «Сохранено» означает подтверждение сервера; при обрыве связи рисунки открытой страницы сохраняются в браузере и отправляются после восстановления. Изображения имеют отдельную очередь загрузки; не закрывайте страницу при сообщении о незавершённой загрузке.

Работа без сети поддерживается на уже открытой странице. Для открытия каталога/оболочки нужен сервер; service worker для полностью автономного запуска пока не добавлен. IndexedDB не защищает от очистки данных браузера и не заменяет резервную копию.

Согласованную резервную копию можно делать **при работающем сервере**:

```bash
npm run backup
# Или в конкретный новый файл:
npm run backup -- /путь/к/копии.sqlite
```

Скрипт использует SQLite Online Backup API и `integrity_check`, не перезаписывает существующий файл. Копия содержит также изображения и ключи доступа. Храните несколько версий на другом диске. Обычное копирование только `.sqlite` работающей WAL-БД может потерять последние изменения.

Для восстановления:

1. Остановите сервер.
2. Перенесите весь старый каталог `data` в резервное место (включая `-wal` и `-shm`).
3. Создайте новый `data` с правами 700 и положите проверенную копию под именем `board.sqlite` с правами 600.
4. Запустите сервер и проверьте доски. В контейнере файл должен принадлежать пользователю `node` (uid 1000).

Для переноса сохраните такую копию и ключ владельца, разверните тот же commit/lockfile, восстановите БД до первого запуска. При переходе на другой hostname восстановите owner-key через интерфейс. После восстановления старого backup ранее подключённый браузер может дослать свои более новые offline-изменения — учитывайте это при целенаправленном откате.

## Тесты и качество

```bash
npx playwright install chromium --only-shell
npm run check
```

`check` запускает TypeScript, unit/integration, Chromium E2E, проверку пера на отдельной production-сборке и рабочую production build. На чистом Linux CI зависимости Chromium ставятся `npx playwright install --with-deps chromium --only-shell`.

- `npm test`: геометрия, CRDT-конфликты, права, пагинация, два WebSocket-клиента, reconnect, запись на диск, restart и освобождение комнат.
- `npm run test:e2e`: реальные жесты, L/C, стили, выделение/копирование, undo/redo, страницы, перезагрузка, два независимых браузера и offline/reconnect.
- `npm run test:e2e:production`: постоянная толщина пера на настоящей production-сборке; данные и сборка находятся во временном каталоге.
- `npm run bench`: синтетический каталог 500 досок / 10 000 страниц и загрузка CRDT-документа 10 000 объектов. Последний замер — `docs/BENCHMARK.json`; это не benchmark рендеринга и не обещание такого же времени через интернет.
- `.githooks/pre-commit` выполняет полный `check`. Он подключается после `npm ci`; проверьте `git config --get core.hooksPath`. Если у вас уже свой hook, установщик его не перезаписывает — добавьте `npm run check` туда.
- GitHub Actions запускает те же проверки на push/PR. Локальный hook можно обойти `--no-verify`, поэтому CI тоже необходим. Защита ветки на GitHub должна настраиваться отдельно.

Результаты первоначальной проверки и состояние рабочего запуска — [VERIFICATION.md](docs/VERIFICATION.md).

Браузерные тесты используют временную БД, отдельные профили и порты 4310/4311. Они не трогают пользовательские доски.

## Почему эта основа и куда развивать

Подробное сравнение tldraw, Excalidraw, Fabric/Konva и ExcaliDash, лицензии и первичные источники — [исследование](docs/RESEARCH.md). У современного tldraw production требует отдельной лицензии; MIT Excalidraw позволяет независимо размещать и расширять эту доску.

[Архитектура](docs/ARCHITECTURE.md), [план](docs/PLAN.md) и [инструкции агентам](AGENTS.md) фиксируют ключевые решения. Дальше: импорт листков/PDF и LaTeX, геометрические построения, корзина/история, аккаунты и роли, квоты, метрики и затем распределение комнат по серверам.

Нет гарантии отсутствия зависаний при произвольно большой активной странице. Защита от роста архива уже заложена: сцены изолированы, списки ограничены, закрытые комнаты выгружаются. Большую задачу разумно разбивать по страницам.
